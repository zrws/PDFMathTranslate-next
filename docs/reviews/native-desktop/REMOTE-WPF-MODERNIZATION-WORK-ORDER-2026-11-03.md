## 1. 先完成 P0 安全门，不重做已关闭的工作

先读取 `docs/specifications/native-desktop/p0-reference/` 中的历史 CASE_MANIFEST、CHANGE_IMPACT、PLAN 与 README，建立并独立审核本电脑新轮的计划和用例清单；保留冻结用例的原始语义，不把这些规格文件当运行证据。先参数化或自动发现 RepoRoot、InstallRoot、PythonExe 和 EvidenceRoot，修复包括 `p0_negative_tests.ps1` 在内的原电脑绝对路径默认值；禁止假定 `D:\paper\pdf2zh-install-test`、原电脑 Python/缓存/样本在本电脑存在，也禁止静默下载依赖以绕过离线测试。缺少运行依赖时记录阻塞并继续静态修复/桩测试。

逐项以最新安全门报告为准，修复 **B1、B2、M1、M2、M3、M4、M5**，保留旧失败证据，所有新运行使用全新且唯一的 run ID。原电脑旧失败证据未附带时明确标为不可用，不推断其成因或补造文件。最少完成：

- B1：以当前脚本新跑 recovery negative test，产出完整 8 条断言矩阵和 4 份 stub 日志；解释旧 run 缺 3 条断言和日志的原因，旧目录不覆盖、不删。
- B2：修复 `p0_baseline.ps1` 的 `-OutDir` 被 PowerShell 大小写不敏感变量赋值覆盖的问题；默认输出根指向本轮新证据根，并用干跑/测试证明 recorder 传入路径确实生效。
- M1：统一 recorder、seal、checker 的 `entry-run` 目录命名/扫描/coverage 映射，使 seal 和 checker 能发现同一个 run，并对缺少必需匹配项失败关闭。
- M2：矩阵选择必须排除 `matrix-selftest-*` 与 reuse-probe，按真实运行标识/结构确定矩阵；不能让故意含 FAIL 的自测样本被当成最终矩阵。
- M3：将 entrygate、env restore、guard mutations、empty-host 等子驱动默认输出位置改到当前轮的新证据根，证明全量调用不会污染旧轮目录。
- M4：attribution 在写入任何内容前拒绝已存在的输出目录/结果文件，不删除旧 JSONL。
- M5：增加资产清单损坏、空清单、缺必需类别、hash 子进程失败的负向用例；若某项受环境限制不能运行，机器结果明确标为 `unverified`，不得宣称关闭。

同时复核旧审核 R1–R5 的修复仍在当前代码中，尤其是严格数字地址校验、子进程隔离、实际失败原因、实际退出码与 checker 错误计数。安全测试只允许使用纯本地桩、隔离临时目录和文档测试地址；禁止真实外网连接、真实翻译、下载、用户缓存/历史目录访问、系统防火墙或全局环境修改。

对每个修复先做与风险相称的短验证；生成新证据时记录脚本哈希、实际启动参数、PID/进程身份、预期/计划/实际退出码、stdout/stderr、清理结果和覆盖映射。checker 自身要有干净通过、错误原因错配、证据缺失、哈希漂移、旧目录复用等变异自测。请安排未参与实现的子代理独立复审；修复其阻断项后再复审一次。只有安全门通过、机器证据可复核、最终 checker 真实退出为 0，才把 P0 标记通过。无需重跑已关闭且与这些修复无关的历史性能基线。

## 2. 随后完成 P1：可用的原生 WPF 工作台

通过 P0 后，按既有方案实现真实 WPF 入口与业务流程，而不是只改色彩或做静态样机。复用 `WPF UI` 和 `CommunityToolkit.Mvvm` 的稳定版本；默认启动路径不再依赖 WinForms/WebView2/HTML 页面承载主 UI。Python 继续负责排版、公式、任务和翻译；不得重写 BabelDOC 算法或换成模拟翻译。

交付一个统一任务状态源和可操作的桌面工作台，至少包括：

- 首页/工作台：清晰的文件导入/拖放、待翻译文件、源语言与**显式可见的目标语言选择**、引擎/必要翻译选项、目标目录、主操作与错误恢复状态。默认目标语言可以保留，但每次提交前必须让用户看见最终语言组合，禁止设置未选择时仍给出“成功翻译”的误导状态。
- 任务队列/历史：主页和队列共用同一任务快照与进度；上传、等待资源、解析、翻译、排版、导出、完成/失败/取消阶段分别显示；支持查看详情、取消、重试、打开结果和打开目录。终态历史分页/虚拟化，活动任务优先，取消和提交竞态有测试。
- 保存路径：保存并展示默认下载/导出目录；首次输出前可以选择目录，单任务允许覆盖；重启后设置保留。输出按 `PDF名_yyyy-MM-dd` 建目录，多版本不互相覆盖，冲突时产生稳定版本名并记录实际保存路径。
- 预览、资源与设置：按需加载预览、分页与失败/无资源状态明确；资源下载可显示阶段和进度且与翻译进度区分；设置页体现有效生效值，不能只更新 UI 而后端仍使用旧默认值。
- 中文产品化：导航、菜单、验证、错误、安装器提示全部中文且用词一致；控件键盘可达、焦点状态清楚、文本缩放/高 DPI 不溢出；首次启动、空队列、无资源、服务未就绪、引擎错误、磁盘不足和更新失败均有明确状态。

界面按高频 PDF 翻译工作流设计成紧凑、层次清晰的桌面应用。使用原生窗口、导航、表格/列表、菜单、对话框和图标语义；避免把网页截图嵌入应用、嵌套卡片、巨大营销式首屏或纯装饰动画。先画/描述目标信息架构，再直接实现可点击、可键盘操作的真实流程；最终提供主窗口、队列、设置/保存目录等关键状态截图和逐条验收记录。

## 3. 资源占用和体积优化必须有数据

- 保留已核准的窗口可用/API 可用/资源可用三态启动模型；空闲不加载 ONNX/布局模型、不驻留翻译 worker、不反复全量轮询或刷新整页任务。
- 事件优先采用已定义的 SSE/reconnect/snapshot 契约，保证断线补快照、实例重启识别、序号去重；必要轮询必须退避且只拉增量。
- 翻译任务默认并发 1；清楚区分文档并发、布局线程、远程 QPS、资源下载和预览。UI 提供简单档位，后端记录并使用最终生效值；不得靠静默关掉用户功能制造低占用。
- 预览使用可取消的按需渲染、页数/尺寸上限和有界缓存；翻页时取消过期请求，空闲渲染进程可退出。
- 对 CPU、GPU、内存、线程、磁盘、冷/热启动、空闲态与样本翻译分别给出基线和优化后测量，工具条件和样本一致；GPU 默认不启用，不能因检测到独显自动切换。不能实测的项标为待验证，不许给推测百分比。
- 从锁定依赖的洁净环境构建；分别记录安装包压缩体积、解压安装体积、首次资源下载、运行缓存。删除依赖前提供依赖图/运行测试证据；不要把缓存/模型复制进 Git。
