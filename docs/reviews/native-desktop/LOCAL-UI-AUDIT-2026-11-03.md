## 依据与设计判断

面向每天翻译科研 PDF 的 Windows 用户，采用紧凑的文档工作台。按工单将 guo-taste-design-2 的层级、单一强调色、表面区分、状态、对齐与可访问性检查映射到原生控件；已读取其 SKILL.md 和 linear/DESIGN.md。技能本身不面向密集工作台，故依用户明确要求，不采用营销首屏、图片、品牌字体、大标题、渐变或网页组件。Linear 仅提供克制层级参考；实现时 WPF UI 与系统主题是唯一 token 来源，中文使用系统字体。

## 当前结构与高频路径

- launcher/PDFMathTranslateLauncher.csproj：net8.0-windows / UseWindowsForms / WebView2 1.0.2792.45，尚无 desktop 工程。
- webui/index.html：工作台、输出、术语表、队列、设置五页。工作台左侧文件/语言/输出选项多层卡片，右侧小预览/进度/下载；目标语言已显式存在，不将其误报为完全缺失。设置页已有默认下载目录，迁移须保留行为。
- 核心路径：导入 PDF → 源/目标语言 → 引擎有效值与输出种类 → 入队 → 解析/翻译/排版 → 预览 → 导出到默认或覆盖目录 → 查看实际版本路径。
- 静态问题：参数占据主工作区，预览空间偏小；同一保存动作分散在进度与输出页；全局“保存设置”与提交有效配置关系不直观；后台资源/接口/窗口三态需要独立呈现。不能从静态 HTML 推断实际任务同步、DPI 或可点击状态已通过。

## 目标信息架构

主窗口 FluentWindow；左侧可折叠 NavigationView：工作台、任务、结果、术语表、设置。顶部仅标题/当前服务状态；不做巨大欢迎区。

工作台 Grid：文档列表 220 DIP、中心可伸缩原文/译文预览、参数栏 280 DIP；GridSplitter 可调。参数栏常驻源语言、目标语言（“简体中文（默认）”）、有效引擎与模型、输出种类、完整保存目录；高级参数折叠。底部固定提交/取消及选中任务阶段，提交前显示最终语言组合与资源档位。

小于 1100 DIP 时预览采用原文/译文标签，参数收为可展开侧栏，始终可看到目标语言与提交；最小 900×620 DIP。正文14 DIP、辅助12-13 DIP、标题20 DIP，4/8 DIP间距，控件基于内容测量。系统高对比时不强制品牌色。

任务页虚拟化 DataGrid，活动优先、终态分页，所有页面绑定同一个 TaskStore。阶段区分上传/等待资源/解析/翻译/排版/导出/完成/失败/取消；取消中是明确中间状态。详情显示不可变配置、错误恢复与实际保存路径。无结果不能出现“已成功保存”。

设置页按翻译服务/资源/保存/外观与更新分组。共享设置只经后端 API 写入，读回实际生效值。保存目录选择使用原生文件夹对话框；失败保留原值。预览只按文档/页/大小变化按需加载，不因进度事件刷新。
