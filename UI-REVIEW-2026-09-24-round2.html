一、新增：应该修的问题

P1 确认弹窗没有焦点陷阱，Tab 会跑进被遮罩挡住的页面

打开「清空翻译记录」确认弹窗后的实测：

DIALOG: aria-labelledby=无  可聚焦元素 全页=21 弹窗内=2  当前焦点=button.btn.btn-destructive

弹窗打开时，整个文档里还有 21 个可聚焦元素，弹窗内只有 2 个（取消 / 确认）。继续按 Tab，焦点会依次落到侧栏导航、顶栏按钮这些被半透明遮罩盖住的元素上 —— 用户在操作一个"看不见但仍然可获得焦点"的界面。第一轮从代码推断过这一点，本轮用数字坐实了。这属于 WCAG 2.4.3（焦点顺序）问题。

还有两个同源小问题：aria-labelledby 没有关联标题（屏幕阅读器读弹窗时不知道标题是什么）；关闭后焦点不会回到触发它的按钮上。

建议改法（app.js:92-136 的 dialog()）：

// 1. 标题关联
var titleId = "dlg-" + Date.now();
// h2 加上 id="titleId"，dialog 加上 aria-labelledby="titleId"

// 2. 焦点陷阱：在 overlay 上监听 Tab，把焦点圈在弹窗内
overlay.addEventListener("keydown", function (event) {
  if (event.key !== "Tab") return;
  var items = overlay.querySelectorAll("button, [href], input, select, textarea");
  if (!items.length) return;
  var first = items[0], last = items[items.length - 1];
  if (event.shiftKey && document.activeElement === first) { event.preventDefault(); last.focus(); }
  else if (!event.shiftKey && document.activeElement === last) { event.preventDefault(); first.focus(); }
});

// 3. 破坏性确认默认聚焦「取消」，Enter 误触的代价更小
var initialFocus = opts.destructive
  ? (overlay.querySelector('[data-role="cancel"]') || confirmBtn)
  : confirmBtn;
initialFocus.focus();

// 4. 关闭时把焦点还给触发元素
// dialog() 增加参数 trigger；finish() 里 trigger && trigger.focus()

P1 QPS 输入框在后端省略字段时显示字面量「undefined」

app.js:1094-1095，相邻两行，一个有保护一个没有：

if ($("qps")) $("qps").value = settings.qps;                                            // 1094：无保护
if ($("workers")) $("workers").value = settings.pool_max_workers == null ? "" : settings.pool_max_workers;  // 1095：有保护

实测把后端返回里的 qps 字段去掉后，QPS 输入框渲染出字面量 undefined，而同屏其它字段都正常显示为空。此时用户只要点一次「保存设置」，parseInt("undefined") 得到 NaN，isNaN 挡住了写入 —— 所以不会写坏配置，但界面上出现一个看不懂的 undefined，且用户无法在不改它的情况下理解这个框的当前值。

改法：与下一行对齐 —— $("qps").value = settings.qps == null ? "" : settings.qps;

四、本轮验证为「没有问题」的项

这部分同样重要 —— 它们是容易被怀疑、但实测排除的：

  • 输出卡片行内对齐一致。实测第一行两张卡 top=180 / h=130 / bottom=310 完全相同，chips 与按钮间距都是 12px。截图里看到的"高度不齐"是探针遮挡造成的假象。
  • 文件名省略号正常工作。实测 6 条任务里 1 条超长文件名被正确截断（scrollWidth 超出 21px 处截断），没有撑破布局。
  • 未知 hash 不会白屏。showPage() 对无效页面回落到默认页（app.js:247），直接打开 #不存在的页 也能正常显示工作台。
  • 没有 XSS。任务名、术语、错误信息全部经过 esc() 转义后才进 innerHTML。
  • 破坏性按钮对比度达标。浅色 4.83:1 / 深色 4.87:1，均通过 AA。
  • 限流模式切换正确。QPS / RPM / 并发三态切换时字段显隐、标签换名、数值保留全部正常。
  • 深色主题下全部实测文本对比度 PASS（任务队列页逐项复测）。
